# MyLibrary v1.0.0

Release date: **2026-10-08**. Stable baseline approved by the owner after manual acceptance testing. This release freezes the approved product without changing its database schema or reading model.

## Product and platform

MyLibrary is a local-first Windows 10/11 x64 desktop catalogue for a personal physical book collection. It includes edition-based grid/table browsing, independently managed physical copies, contributors, series, classifications, hierarchical locations, reading tracking, loans, notes, quotes, attachments and custom fields. Search, combined filters, bulk actions and dashboard status shortcuts complement CSV/JSON exchange and protected ZIP backup/restore.

The frontend is React/TypeScript/Vite inside Tauri 2/WebView2. Rust owns SQLite writes, foreign-key constraints, transactions, migrations and managed files. Editions share bibliographic metadata; copies retain independent acquisition, condition, location, reading and lending data. Library entries group by edition ID after copy-level filtering. No records were merged or migrated for this release.

## Privacy and data

No account, server, cloud database, analytics, telemetry or remote logging. Core operation is offline. Optional explicit Open Library ISBN lookup is the only product network feature.

Production data normally lives at `%APPDATA%\com.mylibrary.desktop`: `library.sqlite3`, `covers/`, `attachments/` and `backups/`. Settings shows the resolved path. Production data is outside the repository; test data, media, backups, caches, secrets and build output are excluded from Git.

Before upgrading or uninstalling, create a backup and retain it on another drive. Backup ZIPs include a versioned `manifest.json`, consistent SQLite snapshot and managed media. **Restore Backup** accepts the ZIP directly, validates it in staging, and creates a mandatory safety backup before replacement. Backups are not CSV/JSON catalogue imports. JSON exchange preserves edition/copy groups and locations; full media/history/settings require ZIP backup.

## Rebuilding the source

Check out `v1.0.0` in a separate clean checkout, use its committed npm/Cargo lockfiles, run `npm ci`, then `npm run desktop:build -- --locked`. Do not point a historical build at a newer production database. Verification uses separate data roots.

Recorded environment: Windows x64, Node 24.21.0, npm 11.19.0, Rust 1.98.1 (`48a229cea`), Cargo 1.98.1, MSVC C++ desktop tools/Windows SDK, WebView2 and Tauri's repository-local NSIS tools. Dependency download availability and external toolchains are prerequisites; the tag preserves source and dependency versions, not a hermetic forever-available build environment.

## Known V1 limitations

- English interface; no encryption, sync, permanent Trash purge, barcode-scanner integration or PDF/HTML reports.
- CSV is a partial catalogue format and does not preserve all copy fields or edition grouping. JSON is not a complete application backup.
- Archive limits: 100,000 files and 20 GB expanded. Backups are unencrypted, not automatically pruned, and scheduled only while the app runs. Multi-file restore is not guaranteed crash/power-loss atomic; retained safety archives support recovery.
- Snapshot-based filtering/FTS refresh is intended for personal libraries, not benchmarked institutional collections.
- Native file-picker interaction and NSIS installation/uninstallation/reinstallation were not individually exercised in recorded automation. The acceptance specification retains explicit manual cases. Native OS resize and live Open Library responses were not automated.
- Reading status/counts remain copy-based; grouped cards explicitly identify mixed reading states. Full editor bibliographic edits affect all copies of an edition.
