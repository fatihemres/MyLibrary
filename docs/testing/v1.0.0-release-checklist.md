## Publication procedure and receipt

These steps necessarily run after this document is frozen in the release commit. Their authoritative receipt is the remote Git refs and published GitHub Release, checked by the release execution report; this file is not amended after tagging.

1. Inspect final diff/status; commit `chore(release): finalize v1.0.0`; push normally to origin/main and verify equal refs.
2. Confirm `v1.0.0` does not exist; create annotated tag `MyLibrary v1.0.0` at that verified release commit. Push the tag and verify its remote tag-object and peeled-commit hashes. Never overwrite an existing tag.
3. Create a draft GitHub Release titled **MyLibrary v1.0.0** using the existing tag and release notes. Upload only `MyLibrary_1.0.0_x64-setup.exe` and `SHA256SUMS.txt`. Verify both assets, then publish as a stable release.
4. Download assets through authenticated GitHub access; compare installer bytes/hash with the build and checksum file; verify release is neither draft nor prerelease. Private repository visibility remains unchanged.
5. Create `v1-maintenance` and `v2` from `v1.0.0^{commit}`; push normally. Verify both remote refs equal the release commit. Keep main stable; switch local checkout to v2 with no product changes.
6. Confirm clean status, main/origin equality, annotated tag target, published assets and branch refs; report full commit/tag hashes and known limitations.
