# MyLibrary v1.0.0 acceptance specification

Frozen baseline: the source at annotated tag `v1.0.0`. Release date: 2026-10-08. The owner explicitly approved the current product after manual acceptance testing. That approval is not interpreted as an itemized pass for tests without recorded evidence.

## Execution and evidence

Use a disposable Windows account/VM for installation lifecycle tests. Never uninstall or remove the owner's production data for verification. For application tests, use `MYLIBRARY_DATA_DIR` and `WEBVIEW2_USER_DATA_FOLDER` pointing to a fresh repository-local `.cache` directory. Start with an empty library unless the row says otherwise. Fixture E is one edition with two copies (C1/C2), different condition/acquisition/location values, 200 pages and a managed test cover. Fixture L is **Study → Bookcase 1 → Shelf 1**, plus Shelf 2. All content is synthetic.

Evidence codes: **F** = `src/domain/library.test.ts`; **N** = `src-tauri/tests/integrity.rs`; **D** = `scripts/desktop-smoke.mjs` operating the real Windows executable. Exact test names are mapped below. **Passed** means the stated assertions have recorded automated evidence; **Partial** identifies narrower evidence; **Not individually recorded** is a manual specification, not an assertion of success. Manual owner approval applies to the release as a whole. See [VERIFICATION](../../VERIFICATION.md) for final run counts, hashes and boundaries.

IDs are permanent. Retain these cases unchanged for historical V1; add new versioned specifications for later releases.
